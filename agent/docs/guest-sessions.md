# Общая сессия посетителя

- Статус: реализовано, 2026-11-16.
- Основание: пользователь подтвердил расширение существующего session-first flow.
- Репозитории: Identity, Client Gateway, Socket Gateway, Cart, Desktop UI; ветка master.
- Объём: гостевой контекст, его жизненный цикл, HTTP/cookie transport, совместимость с аккаунтами и первый потребитель Cart.
- За пределами задачи: интерфейс входа и корзины витрины, Order/Payment, сессии mobile, административные операции над гостями.

## Назначение и владельцы

Гостевая сессия — общий контекст посетителя сайта Sellgar. Она существует до
создания корзины и не зависит от Cart. Другие процессы могут использовать того
же владельца через проверенный серверный контекст. Выдача credentials,
валидность, продление и отзыв принадлежат Identity.

Identity хранит `session.uuid`, `session.owner_uuid` и nullable `session.user_uuid`.
Аккаунту соответствует owner_uuid=user_uuid; его разные сессии используют одного
владельца. Гость получает случайный UUID владельца и отдельный UUID сессии без
создания User. Идентификаторы не меняются при ротации credential. Частичный
уникальный индекс запрещает повторно назначать гостевого владельца другой сессии;
проверка в БД запрещает расходиться владельцу и пользователю аккаунта.

`ownerUuid` передаётся только между доверенными серверными компонентами. Доменный
сервис использует его для принадлежности данных; данные конкретного посетителя
не становятся общедоступными из-за отсутствия аккаунта. Доступ к отдельным
операциям определяется их контрактом. Админка требует пользовательскую сессию.

## HTTP и клиент

| Endpoint Client Gateway | Поведение |
|---|---|
| POST /v1/auth/session | Сохраняет действующий контекст, продлевает гостевой или создаёт гостя при отсутствии/завершении сессии |
| GET /v1/auth/session | Проверяет текущий контекст без создания сессии и продления активности |
| POST /v1/auth/login | Проверяет пароль, создаёт новую сессию аккаунта, завершает прежнюю гостевую |
| POST /v1/auth/logout | Отзывает текущую сессию и очищает cookie |
| POST /v1/auth/socket-ticket | Проверяет существующую сессию без продления и выдаёт короткий ticket существующего канала Cart |

Публичная сессия: `{sessionUuid, userUuid: UUID | null, expiresAt}`. В браузер
не возвращаются ownerUuid, credential, hash, команды закрытия владельца и outbox.
Credential хранится в существующей HttpOnly cookie Client Gateway, SameSite=Lax,
Secure в окружениях HTTPS, с persistent Max-Age до срока сессии. Стабильный
x-device-id — привязка браузера, а не credential и не способ найти чужую сессию.

`SessionInitializer` входит в initializers DesktopApplication. На SSR запросов
сессии нет; браузер инициализирует её до готовности приложения. Application-owned
SessionService сериализует session/login/logout через Web Locks между вкладками,
выдаёт общую привязку устройства из localStorage, сообщает подписчикам новый
контекст. BroadcastChannel передаёт сигнал смены контекста, после которого другая
вкладка проверяет сессию через gateway. Cookies и credentials не пересылаются в
BroadcastChannel. Требуются современные browser Web Locks и BroadcastChannel;
для localhost доступен secure context, в production требуется HTTPS.

Гостевой срок — 30 дней после последней подтверждённой активности. Начальный
визит, возвращение к видимой вкладке и действия пользователя подтверждают
активность через POST /session. Частые действия объединяются в один запрос в минуту.
Продление использует существующую ротацию секрета и обновляет cookie и expires_at.
Пассивные HTTP-чтения, socket tickets, Identity session.check и живой сокет не
продлевают гостевой срок. Обычный механизм renewal аккаунтов сохранён.
Недоступность Identity не очищает cookie и не превращает посетителя в нового гостя.

## Завершение владельца

После проверки пароля одна транзакция Identity заменяет сессию аккаунта в той же
области user/fingerprint/clientType/gateway, отзывает прежнюю гостевую сессию и
записывает `identity.owner.closed.v1` в `session_owner_outbox`. Ошибка транзакции
откатывает все изменения. Неверный пароль не меняет гостя. Продление конкурирует
с отзывом через условную запись активной, ещё не истёкшей сессии.

Такая же запись события выполняется при отзыве гостя и его истечении. Worker
завершает истёкшие гостевые сессии без повторного визита. Событие содержит
`eventUuid`, `eventType`, `schemaVersion`, `producer`, `ownerUuid`, `occurredAt`, `reason`.
Публикация идёт в общий AMQP_EVENTS_EXCHANGE после commit, с broker confirm,
повтором и lease для восстановления после остановки publisher. Доставка at least
once. Завершение сессии аккаунта не завершает его owner и не публикует это событие.

Identity не вызывает Cart. Cart подписывается через собственный integration
controller и вызывает существующий closeOwner с UUID события как внутренним
ключом повтора. ACK выполняется после commit; некорректные события отправляются
в DLQ, временные ошибки повторяются. Закрываются корзины всех магазинов прежнего
владельца; tombstone не позволяет запоздавшей команде создать их снова. Закрытие
асинхронно; отзыв сессии сразу прекращает доступ через gateway и сокеты.

Identity при входе сам не переносит данные между владельцами. Для Cart принята
политика закрытия прежних корзин. Другие сервисы определяют собственную реакцию
на жизненный цикл владельца. После logout клиентская SessionService сначала
завершает аккаунт, затем инициализирует нового гостя; старый гостевой контекст
не восстанавливается. Ошибка нового bootstrap не восстанавливает старую cookie.

Socket Gateway сохраняет проверку ownerUuid и sessionUuid у приватного канала
Cart. У гостя ticket без sub и cursor.user_uuid=null; фиктивный пользователь не
нужен. Такая сессия не проходит в административные broadcast-каналы. Проверка
Identity перед replay/live и короткая lease прекращают доставку после отзыва.

## Конфигурация и rollout

- Identity: AMQP_EVENTS_EXCHANGE обязателен и совпадает с общим exchange Cart;
  GUEST_SESSION_IDLE_TIMEOUT_MS по умолчанию 2592000000.
- Identity migration: GuestSessions1794870000000. Существующим аккаунтам
  backfill owner_uuid=user_uuid; их сессии сохраняются.
- Socket migration: GuestSessionCursors1794870001000. Существующие курсоры сохраняются.
- Применить миграции, развернуть Cart consumer с durable queue/binding, затем
  Identity publisher, gateway и витрину. Очередь потребителя должна существовать
  до первой публикации: topic exchange не хранит события для будущих очередей.
- Локальная витрина — 3100, Client Gateway — 4030. CORS Client/Socket должен
  включать точный origin витрины; origin админки остаётся отдельно разрешённым.
- Штатный TypeORM TS CLI Identity требует ts-node. При его отсутствии после
  yarn build:identity_srv выполнить `node node_modules/typeorm/cli.js -d dist/data-source.js migration:run`.

## Проверка

`node agent/scripts/smoke-client-cart-socket.cjs` использует случайные схемы,
очереди и exchange, реальные Identity, Cart, HTTP и Socket. Проверяет аккаунты и
гостей, 30-дневный срок, отсутствие корзины при создании сессии, сохранение owner
при продлении, отсутствие продления от фоновых запросов, guest ACK без User,
изоляцию владельцев, ошибочный/успешный вход, отсутствие merge, новое гостевое
состояние после выхода, истечение без визита и закрытие всех магазинов после
восстановления остановленного Cart consumer. Тестовые схемы и очереди удаляются.

Браузерный smoke выполняется только в браузере Codex: localhost:3100, новая
вкладка и повторный визит сохраняют session/owner, срок продлевается. Админка
localhost:3000/store проверяется отдельно как регрессия аккаунтной сессии.

Проверки реализации 2026-11-16: сборки Identity, Client, Socket, Cart и production
Desktop; Identity 18 unit, Client 43, Socket 24 + 5 PostgreSQL, Cart 15, Admin
Gateway 62; Desktop typecheck/lint и 7 storefront test files. Финальный
изолированный smoke прошёл, включая независимую admin-сессию с той же привязкой
браузера. Browser smoke подтвердил один guest без User, 30 дней срока, сохранение
session/owner во второй вкладке и после закрытия вкладок. Миграции применены
локально; рабочая админка /store повторно загружена успешно. Коммиты и gitlinks
не изменялись.
