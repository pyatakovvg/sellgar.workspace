# SRP — единственная ответственность

Группируй код по связным причинам изменения. Ответственность — не отдельное действие или метод: один сценарий может включать несколько технических шагов.

## Аудит

Найди потребителей выбранной части кода и требования, которые она реализует. Покажи конкретное изменение одного правила, вынуждающее затрагивать независимое правило. Разные источники требований и независимая история изменений помогают установить границу; одинаковые автор или команда её не доказывают и не опровергают.

Проверь и обратную проблему: не распределена ли одна обязанность по местам, которые приходится согласованно менять. Количество импортов, методов и строк само по себе не является замечанием. Если независимые причины не установлены, обозначь неопределённость вместо обязательного разреза.

## Разработка

Размести связанные решения вместе, а изменяющиеся независимо — за подходящей границей. Ею может быть функция, тип, компонент, модуль или иной механизм используемой системы. Выбирай границу по последствиям изменения, а не по обязательной схеме каталогов.

Координатор вправе вызывать несколько зависимостей. Разделение требуется, когда он присваивает самостоятельные правила, а не просто из-за числа вызовов.

## Рефакторинг

Выдели установленную обязанность и переведи её потребителей. Извлечение метода без изменения связанности может улучшать чтение, но само по себе не решает SRP. Сохрани наблюдаемое поведение; особенно проверь владение состоянием, порядок эффектов и освобождение ресурсов, если перенос их затрагивает. Не дроби цельный сценарий на цепь обёрток без самостоятельных причин изменения.

Пример: расчёт результатов эксперимента и оформление печатного отчёта могут меняться независимо. Координация расчёта и печати при этом может оставаться одной операцией.

В результате назови причины изменения, затронутых потребителей, предлагаемую границу и способ проверки. Отсутствие обоснованного разделения — допустимый вывод.

Основа: [Robert C. Martin, The Single Responsibility Principle](https://blog.cleancoder.com/uncle-bob/2014/05/08/SingleReponsibilityPrinciple.html).
