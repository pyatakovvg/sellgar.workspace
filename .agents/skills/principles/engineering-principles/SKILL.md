# Инженерные принципы

Оцени применимость всей таблицы, затем открой SKILL.md нужных принципов. Для короткой правки не загружай неприменимые инструкции и не добавляй механизмы ради соблюдения принципа. Для полного архитектурного аудита явно отрази все строки: вывод или ограничение.

| Принцип | Когда читать |
|---|---|
| [SRP](../srp/SKILL.md) | Меняется владелец правила, смешиваются независимые причины изменения или дробится цельный сценарий |
| [DIP](../dip/SKILL.md) | Независимая политика связана с деталями хранилища, transport или framework |
| [DRY](../dry/SKILL.md) | Одно знание имеет активные независимые копии и требует согласованных правок |
| [KISS](../kiss/SKILL.md) | Поток управления, состояние или механизм сложнее достаточного решения |
| [YAGNI](../yagni/SKILL.md) | Добавляется будущая возможность или сохраняется предположительно устаревшая |
| [ISP](../isp/SKILL.md) | Клиентам навязаны операции, зависимости или обязательные заглушки чужой роли |
| [LSP](../lsp/SKILL.md) | Реализация или test double подставляется под общее поведенческое обещание |
| [OCP](../ocp/SKILL.md) | Есть известная ось вариативности или каскад похожих расширений |
| [APO](../apo/SKILL.md) | Предлагаются cache, memoization, concurrency или иное ускорение; известны ограничения масштаба |
| [BDUF](../bduf/SKILL.md) | Выбирается глубина предварительных контрактов, дорогой миграции или архитектурного решения |
| [Бритва Оккама](../occams-razor/SKILL.md) | Сравниваются несколько достаточных решений с разными допущениями и механизмами |

Для вывода назови конкретный код/решение, сохраняемое требование и последствие. Отделяй чтение скила от его применения: «прочитан» не означает «найдено нарушение». Принципы не требуют иметь по дефекту на каждую строку.

Не объявляй SRP по размеру класса, DRY по совпадению текста, DIP по факту DI, OCP по наличию switch, APO по отсутствию useMemo. Основания и способы проверки находятся в соответствующих SKILL.md; здесь они не дублируются.
