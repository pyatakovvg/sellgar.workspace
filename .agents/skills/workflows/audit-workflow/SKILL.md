# Аудит

Открой [clean-code](../../engineering/clean-code/SKILL.md). Для аудита системы прочитай его [system-audit](../../engineering/clean-code/references/system-audit.md); для одного файла не подменяй узкое review полным системным обследованием.

Подключи [engineering-principles](../../principles/engineering-principles/SKILL.md), [code-formatting](../../engineering/code-formatting/SKILL.md) и профили фактических слоёв из [development-workflow](../development-workflow/SKILL.md#профиль-слоя). Это использование стандартов для проверки, а не переход в режим записи.

## Проверка

1. Зафиксируй границу и карту областей: entrypoints, владельцы, контракты, данные, состояние, ошибки, потребители, проверки и оформление.
2. Для каждой области установи глубину: чтение, static check, тест, runtime evidence или не проверено. Не выдавай глубокий разбор одного механизма за аудит всей системы.
3. Проверь архитектурные границы и читаемость вместе с корректностью. Для системного аудита отрази применимость всех принципов из selector: конкретный вывод, отсутствие доказанного нарушения либо основание неприменимости.
4. Воспроизведи существенный дефект доступной проверкой; если это невозможно, отдели source-based вывод от гипотезы. Не считай отсутствие найденной ошибки доказательством корректности непроверенной области.
5. В read-only режиме используй checks без записи. Не запускай formatter autofix, не переписывай документы и не меняй pointers ради чистого отчёта.

## Результат

Замечание связывает место, факт, последствие, правило, минимальное исправление и проверку. Разделяй ошибки исполнения, архитектурное несоответствие и оформление. Одна причина с несколькими проявлениями не становится несколькими независимыми дефектами.

Сохраняй точные позиции нарушений в полном списке. При большом количестве однотипных стилевых замечаний дай краткую сводку отдельно от списка; не позволяй количеству CSS/spacing-позиций скрыть существенные проблемы. Учитывай классификацию профильного стандарта и явно называй тип evidence; структурный приоритет не выдавай за воспроизведённый crash.

Сообщи проверенные области, выводы без нарушений, выполненные команды и ограничения. Перечисление названий скилов не заменяет результатов их применения. Если пользователь отдельно разрешил исправление, продолжи через development-workflow с тем же scope.
