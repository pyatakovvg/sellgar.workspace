# Маршрут задачи

Сначала прочитай действующие инструкции репозитория и указанный ими проектный индекс. Оттуда получи владельцев, пути, ветки, команды и критерии приёмки. При отсутствии индекса используй ближайшие инструкции и фактические manifests; не придумывай обязательный файл.

## Выбор группы

| Запрос | Основной маршрут | Условные дополнения |
|---|---|---|
| Commit, push, submodules, gitlinks, sync | [git-workflow](../../git/git-workflow/SKILL.md) | Проверки уже выполненной задачи; без нового feature-refactoring |
| Разработка, исправление, рефакторинг, миграция | [development-workflow](../development-workflow/SKILL.md) | Профиль изменяемого слоя, принципы, оформление; runtime по поведению |
| Аудит, review, оценка качества или структуры | [audit-workflow](../audit-workflow/SKILL.md) | Те же инженерные правила в режиме проверки |
| Запуск приложения, локальный stack, диагностика endpoint | [dev-runtime](../../runtime/dev-runtime/SKILL.md) | Контракты проверяемого сценария |

Открой основной маршрут и обязательные скилы, на которые он ссылается. Условные подключай по указанному критерию. Название папки не является выполнением её правил.

Составной запрос выполняй фазами. «Разработай, закоммить и запушь» означает разработку с проверкой, затем Git-фазу. Запрос на запуск не добавляет sync; запрос на commit не добавляет изменение кода. Уточнение пользователя меняет соответствующую фазу, сохраняя остальную разрешённую цель.

## Граница

До записи установи результат, целевые repositories/packages, существующий dirty state и проверки. Используй текущую авторизацию: не запрашивай повторно уже согласованное действие. Не распространяй web frontend-стандарты на backend или mobile.

Проектные сведения принадлежат документации репозитория. Скилы описывают переносимое решение: как выбрать владельца, проверить контракт и выполнить действие. Изменения разрешены только в установленной границе.

В начале работы кратко назови группу и важные условные правила; в конце сообщи результат, evidence и существенные ограничения. Для маленькой задачи не создавай отдельный отчёт о каждом загруженном файле.
